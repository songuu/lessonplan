# 任务恢复管理与告警

管理员入口为 `/admin/recovery`，侧栏“任务恢复与告警”。教师无全局访问权限。页面每5秒读取 PostgreSQL 的运行事实，可暂停刷新、按状态/课题/任务 ID 筛选和分页查看；详情包含投递时间、执行租约、断点指纹、模型调用预算、模型回执、分页事件和关联告警。管理员不因此获得其他教师的教案正文权限。

## 首次入队失败

创建 Run 和 dispatch Outbox 后，投递器先锁定任务，提交本次尝试次数与短期领取期限，再调用 Redis/ARQ。网络失败、超时或无法确认的回执均持久保留，按下一次到期时间重投，API/Worker 重启不重置次数和截止时间。

默认最多6次，指数退避基数2秒、上限60秒，带0.8至1倍抖动；每次投递超时5秒，累计投递期限300秒。恢复批次继承最早投递截止与累计尝试次数；该期限也覆盖两次投递之间的执行时间。维护 Worker 每2秒对账到期意图，本地 inline 模式有同样的周期扫描。生产应保证维护 Worker 常驻。

稳定 ARQ job ID、epoch 和数据库领取回执共同处理未知结果；旧尝试的迟到回执不能覆盖新尝试。达到次数或期限上限后收口 `DISPATCH_EXHAUSTED`，不无限重试。领域事件只有取得 Redis 写入回执后才标为 published；连接不可用时继续保留 pending。

Run 终态后，Outbox 的 cancelled 表示该投递意图已停止调度，不等同于 Run 被用户取消；应始终以 Run.status 判断任务结果。

## 管理操作

“立即重投”只适用于尚有投递预算的待投递任务，或租约已过期且仍有恢复/时间预算的运行。不会抢占有效 Worker，不会复活已完成、失败或取消的 Run，也不会清空调用/质量重试预算。需要重新生成时，由教案拥有者创建新 Run。

操作提交 epoch、投递 attempts 与原因；数据过时返回409，刷新后由管理员重新判断。取消会关闭当前执行权并保留已存断点。重投、取消、告警确认和关闭均记录审计。页面轮询只读，不产生审计洪泛。

## 告警

| 代码 | 含义 | 自动关闭条件 |
|---|---|---|
| DISPATCH_RETRY | 投递暂未获得可靠回执 | 投递或执行恢复 |
| DISPATCH_EXHAUSTED | 投递次数或期限耗尽 | 人工关闭 |
| WORKER_LEASE_EXPIRED | Worker 租约过期并等待接管 | 新执行者获得有效租约，或任务结束 |
| WORKER_RECOVERY_EXHAUSTED | Worker 恢复次数耗尽 | 人工关闭 |
| QUEUE_BACKLOG | 排队年龄达到阈值，默认60秒 | 开始执行或任务结束 |
| LLM_OUTCOME_UNKNOWN | 模型请求已记录，但无法确认完整响应，已阻止自动再次调用 | 人工核对后关闭；关闭告警不恢复任务 |

同一代码与 Run 只保留一条告警；`occurrence_count` 记录信号触发次数，周期扫描的重复观测也会累计，因此不是独立故障事故数。状态为 open、acknowledged、resolved。“确认”表示已接手；自动关闭后保留确认人和时间。已关闭告警若条件再次触发会重新打开，持续异常时人工关闭不能永久压制告警。

本轮提供站内持久告警和结构化日志；尚未接邮件、短信、Webhook 或外部告警平台。日志与管理详情使用受控错误、元数据白名单，避免输出教师正文、模型 Prompt、原始异常和凭证。

## 数据库与配置

迁移0004向 `domain_outbox_events` 新增 `last_attempt_at`、`last_error_code`、`last_error_at`、`dispatch_deadline_at` 四个可空列，新增 `recovery_alerts` 表。0005新增 `llm_invocations` 保存调用意图和原始响应回执。升级前停旧应用并备份，不自动执行删表降级。

配置见 `.env.example` 的 `DISPATCH_*`、`QUEUE_BACKLOG_SECONDS` 与 `WORKER_*`。修改配置后重启 API 和 Worker。当前本地使用 Docker PostgreSQL 的独立 `lesson_assistant` 数据库和项目 Redis，不写其他项目的 `rag_system`。

## 验证边界

自动回归覆盖首次失败、退避、次数/期限耗尽、未知回执、领取中断、旧回执、取消、并发、队首公平、告警去重与重新打开、权限/CAS/审计及页面过时响应保护。真实 PostgreSQL 并发测试仅允许独立的 `lesson_recovery_verify_*` 临时库。

Worker 硬停止后，已落库的完整模块通过输入/内容指纹与质量门验证后复用。0005起，尚未应用但已保存的完整模型响应也可重放，不增加调用次数；没有可靠完整回执的在途调用进入 `LLM_OUTCOME_UNKNOWN`，停止自动生成并保留人工告警。当前Provider没有已验证的结果查询能力，不能消除“模型完成但任何回执均未提交”的窗口。详见[模型调用回执与恢复](模型调用回执与恢复.md)。PostgreSQL 和 Redis 同时不可用时仍需基础设施恢复和持久卷备份。

本轮真实模型演示、DBX 观测及服务恢复证据见[验收记录](verification.md)。
