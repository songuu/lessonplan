# 状态与版本不变量

Run：queued → running → completed / failed / cancelled；终态不可覆盖。数据库partial unique index保证同一Run最多一条终态Event，sequence数据库原子递增，与终态/正文指针同事务提交。

Draft：creating → generating → ready（completion_status=completed，hard_gate_status=passed）；结构化单步后creating/writing，Finalize才ready。失败failed_retryable，用户取消cancelled。只有outline或缺模块不可导出；预览更宽松，带警告冻结实际版本。

Module生成与确认独立。current_module_version_map是正文唯一指针，confirmed_version_id才进入稳定依赖。未保存候选仅在PolishSession/Message中；保存/恢复均新增committed版本、维护parent/version_no、content_version+1并写Outbox。

跨对象写事务按Draft→Run顺序锁定。删除软删并取消全部活跃Run；取消后Worker不得提交版本/候选/文件成功；导出/解析关联状态同事务收口。

已确认上游编辑或重生成后，按注册表依赖图递归标记下游stale并保留正文。stale进入快照/导出警告，系统不静默改写。教学过程新outline清除旧确认，activities必须人工确认；教师确认环节/顺序/时长优先。

唯一约束分别覆盖教师/request_id、教师/idempotency_key、draft/module/version_no、草稿前台活跃Run与Run终态事件。PostgreSQL行锁与约束防护多进程；SQLite仅便携验证。

结构化目录按确认顺序解锁：未生成的后续模块不能跳过前序进入，确认当前模块后进入下一个待确认模块。已有完整正式正文始终可回看；若前序修改后待重新确认，后序已有正文只读，前序确认后恢复编辑和生成操作。教学过程仅有大纲时不视为完整历史模块。

回看已确认模块时，底部显示“继续下一步”，切换到下一个启用模块，不重复提交确认或变更版本；最后一个已确认模块显示“当前模块已确认”。执行中、存在未保存修改或前序待确认时仍禁止继续操作。

进入已解锁、尚未生成的pending模块时自动发起当前模块生成，无需再次点击生成按钮；目录进入和确认后继续均适用。已有正文、大纲或本地未保存内容不自动重生，教学过程仅自动生成大纲，确认大纲与生成详细活动仍保留人工步骤。每次打开教案时同一模块最多自动尝试一次，启动失败可显式重试；失败/取消的教案或任务不静默重跑。正在跟踪的Run到终态后，须成功读回正式状态再判断是否自动生成，防止旧pending快照造成重复请求。

同一教案的生成、重新生成、模块润色及反思润色共用前台任务互斥。任务queued/running期间可以回看已生成模块，不能从旧模块再次发起AI任务或保存/恢复正式版本；润色会话创建也在Draft锁下检查活动任务。生成/确认入口均检查前序已确认。相同幂等请求仍重放原Run，不新增任务。

前端以服务端active_run_id优先跟踪当前任务，旧URL中的终态Run不能解除新任务的锁。连接异常不代表任务已结束，状态未确认前保持禁用，可通过重新读取恢复跟踪；收到真实终态后恢复操作。请求提交使用同步门控，避免按钮禁用渲染前的连续点击重复提交。只读状态保留本地润色候选，但不能采用到编辑器。
