# 产品事件与运行指标

入口 `/api/v1/analytics/events`。仅接受event_name白名单及draft_id/run_id/module_id/format/mode/duration_ms/error_code属性，丢弃其他属性，不采集教师正文、Prompt、密码或token。前端只在对应业务成功后发送一次；埋点失败不影响业务成功。

| event_name | 触发 |
|---|---|
| generation_started | 创建/发起成功，含模式与Run |
| module_confirmed | 确认成功 |
| polish_started / polish_applied | 润色Run创建 / 候选采用 |
| module_saved / version_restored | 模块保存 / 历史恢复成功 |
| preview_opened / export_started | 快照预览 / 导出创建成功 |
| reflection_saved | 正式反思保存成功 |
| sse_reconnected / sse_failed | 连接重试 / 流错误，保留关联Run |

业务事实以Draft/Version/Export/Reflection为准；模型调用以CallLog为准；产品行为以AnalyticsEvent为准。教师停留时长不推断满意度。

Issue record_kind=issue为追加问题事实，sample为按user/workflow/hour聚合的操作分母。成功率=sum(success_count)/sum(sample_count)，取消与失败分开；fallback最终成功仍记录degraded_count和独立问题事实。概率需在同sample_space/同时间窗内按受影响样本去重，不能直接用所有Issue行数除以所有样本。管理端“问题数/问题列表”只读issue，不把成功样本当故障。
