# 后端领域与执行设计

FastAPI Router负责HTTP、认证和请求Schema；Service负责状态与事务；ORM负责业务事实；ARQ任务入口只做认领、时间预算与执行边界；AI Runtime及文档/存储Adapter不拥有数据库业务终态。

一键：校验字典/幂等→冻结配置与风格→queued Run+dispatch Outbox提交→稳定job ID入队→Worker CAS认领→确定性蓝图+单次完整生成→临时模块流→质量门/白名单修补→同事务写版本/指针/质量/调用/快照/唯一终态→后台Review。

结构化：首次规划并持久化蓝图，按确认依赖生成单模块；教师确认后推进。教学过程先outline，允许增删排序改时长，确认后activities逐环节输出；只有全部启用模块正式完成并确认才Finalize。

编辑与润色：手动工作副本和AI候选均不覆盖正式正文；保存校验三重版本锁，新建committed版本并按依赖图标记下游stale。恢复旧内容也新增版本。编辑器按模块/版本隔离撤销栈；保存期间锁定输入/导航防止异步覆盖。

预览与文件：快照按正式版本映射组装；导出强制ready/completed/passed和完整模块。文件写入后读取字节验证，再保存成功receipt；取消不允许晚到提交。个人库解析与缩略图独立队列，chunks持久化；DOCX预览明确为解析重排。删除与解析统一Run→Document锁序，失败/取消清理临时PNG，删除文件另有Outbox补偿。

运行可靠性：跨Draft/Run写事务统一Draft→Run锁序；队列为空回执不能假成功；published但丢失的queued任务对账恢复；超时/取消/进程中断分别收口。数据库Event/Run是事实源，Redis PubSub只作after-commit唤醒，失败可退回轮询。

安全：教师资源所有权、管理员审计、JWT撤销、生产配置fail-fast。上传在multipart解析前鉴权并累计限流，限定单文件和有界并发；ZIP/PDF限制与原生PDFium进程锁降低解析风险。请求/日志不包含Secret或完整Provider异常。

本仓库是模块化单体Workflow Agent，不是自主工具平台或多Agent分布式业务系统。代码实现所用的开发子agent不属于产品运行架构。
