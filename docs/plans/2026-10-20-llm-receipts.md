# LLM 调用回执与恢复重放

本任务由2026-10-20用户“直接补充”授权，作为当前恢复 Sprint 的 Work 扩展；不改变旧验收事实、不提交或推送、不写全局学习记录。

## 可观察验收

- 调用前独立提交唯一调用意图，键不随 Worker epoch 变化；上下文指纹包含教师/租户、Run、输入/资产和模型配置。
- 模型完整原始响应、hash、受控调用信息先以短事务持久化，再推进预算、质量门、断点和正式业务提交；完整回执重放不产生新调用、不增加已用预算。
- 恢复覆盖蓝图、一键批量、结构化、活动、润色和审查；未完成的同一次质量尝试可重放，真实质量失败仍受现有预算限制。批量响应可以与已落库模块断点一起恢复。
- in_flight 或无可靠回执的结果进入 LLM_OUTCOME_UNKNOWN，禁止恢复时自动重复付费调用；当前兼容Provider无已验证结果查询/幂等能力，不伪造支持。网络/超时等不确定响应在回执模式下不自动切备用模型。
- 旧传输者可给原始调用归档不可变迟到回执，但不能获得业务写权限；取消/删除/终态仍受现有fencing约束。最终applied标记与业务结果同事务提交。
- 管理详情只返回调用状态、指纹、用量、Provider请求编号等安全元数据，教师403，原始正文/Prompt/密钥不进入管理响应。未知结果留下持久告警。
- 先失败测试再实现，完成相关与全量回归、真实PostgreSQL并发和迁移检查；本地实例若需迁移，先确认目标/活动任务并备份，保持用户配置和其他项目数据。

## 已知边界

模型服务完成但任何可靠存储均无回执时，当前Provider无法对账，选择停止自动生成以避免重复计费。该窗口无法由本地事务或Redis锁消除；允许用户明确创建新的生成任务。当前先使用PostgreSQL正文列保存不超过现有4MiB上限的响应，不引入对象存储双写或新独立网关部署。
