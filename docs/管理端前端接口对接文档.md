# 管理端接口

前缀 `/api/v1/admin`。Bearer验证后每次回读role=admin/is_active，访问写admin_audit_records。普通教师403。列表不返回密码、完整Prompt或教师正文。

| 方法 | 路径 | 返回/约束 |
|---|---|---|
| GET | `/overview` | users/drafts/runs/exports/issues/running计数 |
| GET | `/users?offset=0` | 最近100用户，不含hash/profile/preferences |
| PATCH | `/users/{id}` | is_active/role；不能移除自己的管理权限 |
| GET | `/runs?status=` | 最近100运行metadata，不含payload/result |
| GET | `/issues` | 最近100问题事实 |
| GET | `/audit` | 最近100审计事实；本次访问亦留审计 |

管理员通过显式CLI初始化，无默认凭证，前端不能自行提升角色。

## 恢复管理接口（0004）

以下读取均不写审计，仍逐次校验管理员角色；响应统一由 `data` 包装。可选状态应省略，不能传空字符串。

| 方法 | 路径 | 返回/约束 |
|---|---|---|
| GET | `/recovery-overview` | queued/running/retry_pending/expired_leases/open_alerts/failed |
| GET | `/recovery-runs?status=queued&search=&offset=0&limit=20&attention_only=false` | items/total/offset/limit/server_time；limit最多100；status可取queued/running/completed/failed/cancelled |
| GET | `/recovery-runs/{id}?after=0&limit=50` | run/checkpoints/budget/calls/invocations/events/event_total/alerts；只含运行元数据和指纹，不返正文 |
| POST | `/recovery-runs/{id}/retry` | `{expected_epoch,expected_attempts,reason}`；受控重投，过时/预算不足/有效租约/终态409 |
| POST | `/recovery-runs/{id}/cancel` | `{expected_epoch,reason}`；撤销活动任务执行权；重复取消幂等 |
| GET | `/recovery-alerts?status=open&offset=0&limit=20` | items/total/offset/limit；status可取open/acknowledged/resolved |
| POST | `/recovery-alerts/{id}/acknowledge` | `{reason}`；有条件状态变更及审计 |
| POST | `/recovery-alerts/{id}/resolve` | `{reason}`；只关闭告警，不重置任务 |

原因去除首尾空格后长度4至300；epoch/attempts必须为非负整数。Run summary含 `dispatch`、`can_retry`、`can_cancel`；按钮能力应遵循服务端返回，并处理409刷新，不能自动重复提交。事件payload只投影受控阶段、模块ID、断点键、尝试次数、epoch和错误代码。详细语义见[任务恢复管理与告警](任务恢复管理与告警.md)。

0005新增 `invocations` 数组（按创建时间和ID排序，最多100条），字段为 `id`、`invocation_key`、`step_key`、`attempt`、`call_id`、`call_index`、`route`、`status`、`request_hash`、`response_hash`、`capture_epoch`、`created_at`、`response_saved_at`、`applied_at`、`error_code`，以及可空的 `provider_request_id`、`model_name`、Token用量。后端以标量投影读取，既不读取到响应正文，也不向管理API返回正文、完整Prompt、原始错误或凭证。

回执状态为 `in_flight`（调用意图已保存）、`response_saved`（完整响应已保存）、`applied`（在任务业务事务中记账）、`failed`（明确失败）、`outcome_unknown`（结果不确定）。`applied`不表示原始输出一定通过质量门；质量结果仍看 `calls.validation_outcome`。`LLM_OUTCOME_UNKNOWN` 告警需人工核对，已失败Run不能由“立即重投”复活。

## 执行日志与 Langfuse（0006）

`/admin` 和管理员侧栏均提供“执行日志”，页面路径 `/admin/execution-logs`。以下读取沿用管理员鉴权，未登录401、教师403；响应由 `data` 包装，不返回监控密钥或原始正文。

| 方法 | 路径（均在 `/api/v1/admin` 下） | 返回 / 约束 |
|---|---|---|
| GET | `/execution-logs?run_id=&level=&status=&workflow=&after=0&limit=50` | `items,next_after,has_more,observability`；可选筛选须省略空值；limit为1..100 |
| GET | `/observability` | 当前 API 进程的 Langfuse 配置/发送诊断与 `local` 写入器计数；不是所有 Worker 的聚合健康状态 |

日志按递增 `sequence` 正序读取，下次使用 `next_after`；空页保留原游标，`has_more` 决定是否继续加载。PG 写入通过短事务锁保证取号与提交顺序一致，防止多 Worker 游标遗漏。刷新/自动轮询应保留先前页，event_id 可用于去重；修改筛选时重置游标。未配置 Langfuse 不影响查询。

每条日志字段为 `sequence,event_id,run_id,execution_epoch,trace_id,span_id,parent_span_id,phase,name,run_type,level,status,started_at,ended_at,elapsed_ms,metadata,created_at,workflow_type`。phase为start/end/event，level为info/warning/error；status为running/completed/failed/cancelled/lease_lost/interrupted。`interrupted`表示执行结束时未确认正式结果，不能显示为业务成功。start/end是各步骤当时的事实，不等于任务列表的当前状态。

`metadata`只含受控身份、模型/路由、已知token、首字时间、质量结果和错误码等。未知用量不得补零；回执复用不得再次累计模型请求与费用。教师主题、Prompt、知识片段、教案正文、原始异常及凭证不属于此接口。模板不得渲染任意元数据HTML或将其当链接。

本地trace/span为UUID；Langfuse的Trace ID是UUID移除连字符后的32位小写十六进制，observation ID使用span UUID的低64位。页面同时显示本地与Langfuse Trace ID，复制按钮使用后者。详情的“查看任务恢复”跳转 `/admin/recovery?run_id=<id>` 并自动打开对应详情。部署、初始化账号位置和配置方式见[Langfuse 自托管部署](Langfuse自托管部署.md)。
